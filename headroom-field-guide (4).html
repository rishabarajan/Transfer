Input tokens WHAT SHRINKS

Everything sent to the model is input tokens: your prompt, the conversation history, and, in agent sessions, every file read, command output, search result, log dump, and RAG chunk. You pay per token, so long sessions with heavy tool output add up quickly.

This is the only side Headroom compresses. The ContentRouter detects each block's type and hands it to exactly one specialised compressor. What is never rewritten: your prompt text, system prompts, source code (unless AST compression is explicitly enabled), and short blocks below the minimum-token threshold, where compressing would cost more than it saves.

Documented result: about 20% saved on an overall coding session; 70-95% on JSON, search, and log payloads.

Output tokens NEVER TOUCHED

Output tokens are what the model generates back. Headroom returns every model response exactly as generated; nothing on the reply path is rewritten. That is the dashed return edge along the bottom of the map.

This is a deliberate design boundary: all savings come from shrinking what goes up, never from altering what comes down. It is also why accuracy benchmarks (GSM8K, TruthfulQA, SQuAD, tool-calling) show no meaningful quality drop: the model answers from preserved information, and can retrieve the untouched original whenever it needs it.

Design guarantee: fails open. If any transform errors, content passes through unchanged and the request still goes through.

Provider prefix cache CACHE 1 OF 2

Providers discount repeated request prefixes, but only when the prefix is byte for byte identical between turns. A naive compressor that rewrote old history every turn would silently destroy those cache hits and could cost more than it saved.

CacheAligner exists to prevent exactly that: in the default cache mode only the newest turn is compressed, earlier turns are forwarded byte for byte, history is never dropped or reordered, and system prompts are kept intact.

Dashboard tile: Prefix cache impact, how much the provider's cache is saving you on repeated prefixes.

CCR local cache CACHE 2 OF 2

Compress, Cache, Retrieve. Before any block is compressed, its full original is stored in a hash-indexed local SQLite cache, and a retrieval tool is exposed to the model. If the model ever needs the untouched data, it calls headroom_retrieve("abc123") and gets the original back.

This is what makes aggressive compression safe: the model sees a small version, and the full version is always one retrieval away. CCR is on by default, and originals never leave your machine.

Documented example: 1000 items compress to 15; the original 1000 stay retrievable.

Tool schema trimming OFTEN THE BIGGEST WIN

Agents like Claude Code send every tool definition eagerly on each request, which is pure input-token overhead. Headroom compacts that schema, and headroom wrap claude also sets ENABLE_TOOL_SEARCH=true so tools load on demand natively.

On Claude Code this is frequently the largest single chunk of savings, which is why the dashboard separates it from content compression.

Dashboard tile: Tool search savings. Common confusion: a session can show 29% total while content compression reads 2%; both are correct, the 2% is one component. Trust the total.

The compressor bank ONE BLOCK, ONE COMPRESSOR

Fast native Rust handles the structured formats: SmartCrusher for JSON tool outputs (70-90%), SearchCompressor for grep results (80-95%), LogCompressor for build and test logs (85-95%), plus Diff (40-80%), HTML (70-90%), and Tabular (60-90%) compressors. Code compression (40-70%) is strictly opt-in.

Plain text falls back to Kompress-v2-base, a small ML model trained on agentic traces, run through ONNX Runtime. It downloads once on first use, which is why early requests show only 2-3% savings until it finishes loading.

Savings scale with how repetitive the payload is; dense prose compresses little to none.

Standard operating procedure

Scope: every engineer running Claude Code, Cursor, or another coding agent on local hardware. Part A once per machine, Part B for your agent, Part C every working session, Part D to verify. Every wrap is undone with headroom unwrap <agent>; nothing is permanent, and the worst failure mode is simply no savings.

Part A, install once per machine

  1. Install with Python 3.13 pinned

    uv tool install --python 3.13 "headroom-ai[all]"

    Or with pip: pip install "headroom-ai[all]". Why 3.13: the dashboard's dollar figure uses a pricing library that will not install on Python 3.14+. Token savings still track on 3.14, but the dollar figure stays $0.00.

  2. Verify the install

    headroom --version

  3. Run the health check

    headroom doctor

    If the command is not found, see Troubleshooting below; it is almost always a PATH issue.

Part B, wire up your agent

  1. From your project folder, run the wrap instead of claude

    headroom wrap claude

    Starts a local proxy, installs Serena for semantic code navigation, and launches Claude Code routed through Headroom. Auth and model are preserved automatically. Flags: --code-memory none to skip Serena, --1m for 1M context.

  2. Keep the terminal open while you work

    That terminal is the proxy. Closing it means plain Claude Code: no harm, just no savings.

  3. To undo

    headroom unwrap claude

  1. Install the proxy if not already installed

    pip install "headroom-ai[proxy]"

    The full [all] install from Part A also covers this.

  2. Wrap the extension from your project folder

    headroom wrap vscode-claude

    Patches the official Claude Code extension's settings to route through Headroom.

  3. Reload the VS Code window once

    Command Palette (Ctrl/Cmd+Shift+P), then "Developer: Reload Window." Leave the wrapper terminal running; it is the proxy.

  4. To undo

    headroom unwrap vscode-claude

    Related: headroom wrap vscode covers GitHub Copilot inside VS Code, keeping the model picker authoritative.

Cursor is manual setup: Headroom prints a base URL and you paste it into Cursor's settings. Cursor does not auto-configure the way Claude Code does.

  1. Start the wrapper or proxy

    headroom wrap cursor

    Or headroom proxy --port 8787. It prints a local base URL, e.g. http://127.0.0.1:8787.

  2. Point Cursor at the printed URL

    Settings, then Models (the API / OpenAI base URL section). Set the base URL to the printed address; keep your normal API key and model. Use the exact URL and port printed, since 8787 may be taken.

  3. Keep the proxy terminal running while you use Cursor

    Traffic now flows through Headroom.

Building your own app or agent? Call Headroom inline.

from headroom import compress
from openai import OpenAI

messages = [{"role": "user", "content": "Analyze these results"}]
result = compress(messages, model="gpt-4o")

client = OpenAI()
resp = client.chat.completions.create(
    model="gpt-4o", messages=result.messages)
print(result.tokens_saved, result.compression_ratio)
import { compress } from 'headroom-ai';
const result = await compress(messages, { model });

The npm headroom-ai package is the TypeScript SDK only; the headroom CLI ships only in the PyPI package. Framework hooks: withHeadroom() for the Anthropic and OpenAI SDKs, headroomMiddleware() for the Vercel AI SDK, HeadroomChatModel for LangChain, HeadroomCallback for LiteLLM, HeadroomAgnoModel for Agno.

Troubleshooting

'headroom' is not recognized / command not found

The install landed in a Scripts folder not on your PATH (common with pip --user on Windows). Confirm via the full path, then add the folder to PATH:

# Windows: add the printed Scripts dir to PATH, then reopen the terminal
setx PATH "%PATH%;C:\Users\<you>\AppData\Roaming\Python\Python3XX\Scripts"

# uv installs:
uv tool update-shell

Already-open terminals do not see PATH changes. Always close and reopen, PowerShell especially.

Early requests only show about 2-3% savings

Normal on first run: the text-compression model downloads in the background, and content compression is limited until it loads. Later requests in the same session improve automatically.

Dashboard $ figure is $0.00

You are on Python 3.14+. Token savings still track. For the dollar figure, reinstall pinned to 3.13 and restart the proxy:

pipx reinstall headroom-ai --python python3.13
'Claude Code is sending all tool definitions eagerly' warning

Harmless; Headroom compensates by compacting the schema. To silence it, set ENABLE_TOOL_SEARCH=true before launching, or just use headroom wrap claude, which sets it automatically.

Corporate network / SSL errors on install

A CERTIFICATE_VERIFY_FAILED error usually means SSL inspection. Install Rust first to avoid a build-time download, or use a prebuilt wheel:

pip install --only-binary headroom-ai headroom-ai

How the Tensai team integrates Headroom

The adopted standard for Tensai AI Platform Engineering, drawn directly from the SOP tab. It changes nothing about how engineers work; it changes only how their agent traffic reaches the provider.

  • Wrap mode on engineer workstations. Claude Code sessions (CLI and the VS Code extension) launch through headroom wrap claude or headroom wrap vscode-claude instead of the bare command. Cursor users point the base URL at the printed local proxy. Auth, model choice, and workflow stay untouched.
  • Python 3.13 pinned at install. One version pin keeps the dashboard's dollar figure alive; on 3.14+ token savings still track but the dollar tile reads $0.00 and makes reporting harder.
  • Everything stays on the workstation. Compression, the CCR originals cache, and the dashboard all run locally. No prompts, code, or file contents are sent anywhere else to be compressed, which matters for client codebases like Wickes and Carlyle work.
  • Verification is part of the session, not an afterthought. After a few requests, the engineer confirms the dashboard's Tokens Saved total is moving, and reads the total rather than the content-compression slice. Per-engineer baselines come from headroom savings against real traffic; the team does not quote projected numbers.
  • Rollback is one command. headroom unwrap <agent> restores original settings. Because Headroom fails open, the worst outcome at any point is uncompressed traffic, never a broken agent.
